# 별명·계정·학습 랭킹 배우기

## 사용하는 순서

1. **계정·친구**에서 앞말과 뒷말을 고릅니다. 예: `반짝이는 고래`.
2. 가입 전에 복구 코드를 복사해 본인만 보관합니다. 보관 확인 후 별명을 확정합니다.
3. **학습 랭킹**에 0 XP·레벨 1부터 표시됩니다. 로그인한 상태에서 실습을 완료하면 누적 XP가 오릅니다. 100 XP마다 레벨이 오릅니다.
4. 다른 컴퓨터에서는 **이미 계정이 있나요? 다른 컴퓨터에서 이어하기**에 복구 코드를 입력합니다. 새 별명을 만들 필요가 없습니다.
5. 레벨이 올라도 이름은 그대로입니다. **하루 도전** 탭에서는 별도로 세 문제를 완료해야 도전 점수가 올라갑니다.

이전 자유 입력 별명을 쓰던 계정은 허용된 단어 조합을 한 번 선택합니다. 계정 ID·복구 코드·완료 기록·XP는 그대로 유지합니다. 기존에 이미 유일한 허용 조합을 사용했다면 그 이름을 유지합니다. 혼자 연습에서 얻은 브라우저 XP는 서버 랭킹에 합산하지 않습니다.

## 왜 기존 순위가 안 보였나요?

기존 기본 순위는 **하루 도전 세 문제를 모두 완료한 기록**만 표시했습니다. 조사 당시 운영 데이터는 계정 2개, 실습 완료 0개, 도전 완료 0개였습니다. 가입이나 일반 연습만으로는 그 도전 순위에 나타나지 않는 구조였습니다. 이제 별명을 확정한 계정은 학습 랭킹에 즉시 보이고, 누적 학습과 하루 도전의 순위를 구분해서 설명합니다.

## 먼저 이해하면 좋은 개념

| 개념 | 이 사이트에서의 예 |
| --- | --- |
| 식별자 | `player.id`는 계정의 내부 번호입니다. 이름이 계정 자체는 아닙니다. |
| 인증 | 복구 코드는 같은 계정의 주인임을 확인하는 비밀입니다. 별명만 알아서는 접속할 수 없습니다. |
| 허용 목록 | 준비한 앞말·뒷말만 받아 자유 입력 메시지를 막습니다. |
| 고유 조건 | DB가 같은 별명을 두 계정에 확정하지 못하게 막습니다. |
| 트랜잭션 | 관련 기록을 모두 반영하거나 전부 취소합니다. |
| 멱등성 | 같은 요청을 다시 보내도 계정 생성·XP 지급·하트 차감을 반복하지 않습니다. |
| 서버 검증 | 브라우저가 보낸 점수 대신 서버가 답·소유권·진행을 판단합니다. |

## 주요 코드 읽는 순서

### 1. 허용된 단어로 이름 만들기

`server/names.mjs`의 `NAME_ADJECTIVES`, `NAME_NOUNS`, `composedName()`을 읽으세요. 앞말 80개 × 뒷말 100개 = 8,000개 조합입니다. 화면에서 선택지를 제한하고 서버도 같은 목록으로 검사합니다. 개발자 도구로 자유 입력을 보내도 저장되지 않습니다.

### 2. 동시에 가입해도 이름이 겹치지 않게 하기

`migrations/0003_identity_and_receipts.sql`에 `name_locked=1`인 이름의 고유 인덱스가 있습니다. 사용 가능 확인은 안내일 뿐, 최종 결정은 DB가 합니다. 두 사람이 동시에 같은 이름을 확정하면 한 명만 성공하고 나머지 사람에게 다른 조합을 안내합니다. 이름을 확정한 뒤에는 `server/identity.mjs`의 `saveIdentity()`가 변경을 거부합니다.

기존 계정을 삭제하거나 새 DB를 만들지 않습니다. 중복된 옛 이름은 계정 기록을 보존한 채 각각 한 번 새 조합을 선택합니다. 허용 조합이 모두 사용 중이면 명시적으로 알리고, 다음 확장 때 단어 목록과 마이그레이션을 함께 갱신합니다.

### 3. 응답이 끊겨도 같은 계정으로 이어가기

`site/identity.mjs`는 가입 전에 무작위 `registrationId`와 복구 코드를 준비합니다. 서버는 코드 원문 대신 해시를 보관합니다. 가입 결과를 못 받으면 같은 요청을 재전송하고 `account_requests`에서 이미 생성한 계정을 찾습니다. 요청 ID만 알아서는 인증할 수 없고 복구 코드도 일치해야 합니다. 다른 계정이 이미 접속된 탭에서는 실수로 새 계정으로 바꾸지 않고 현재 계정을 확인합니다.

### 4. 제출 영수증으로 중복 채점 막기

`server/answers.mjs`의 `processAnswer()`를 읽으세요. 브라우저는 답을 제출할 때 요청 ID를 붙이고, 같은 답을 다시 확인할 때 같은 ID를 씁니다. `answer_receipts`는 시도·요청 ID와 답의 해시, 판정 결과를 기록합니다. 같은 ID로 다른 답을 보내면 거부합니다.

영수증 기록·실습 진행·XP 지급·하트 차감은 조건을 건 DB 배치로 처리합니다. 이 배치 안에서 실패하면 전체가 롤백됩니다. [Cloudflare D1의 batch 설명](https://developers.cloudflare.com/d1/worker-api/d1-database/)에서 트랜잭션 동작을 읽을 수 있습니다. 서로 다른 기기의 오래된 단계 제출은 현재 서버 진행을 다시 불러옵니다. 브라우저 임시 저장소에는 답 원문을 저장하지 않습니다.

### 5. 이름을 유지하며 레벨과 순위 계산하기

`server/rank.mjs`의 `learningLeaderboard()`는 계정을 기준으로 완료 기록을 합칩니다. 완료 기록이 없는 계정도 `LEFT JOIN`으로 포함하므로 0 XP부터 보입니다. 레벨은 `1 + Math.floor(xp / 100)`입니다. XP·완료한 서로 다른 실습 수·가입 시각·내부 ID 순으로 순위를 안정적으로 계산합니다. 상위 100명 밖에 있어도 자신의 실제 순위는 추가로 표시합니다.

`site/app.mjs`의 `selectRankBoard()`와 `renderLearningRank()`가 화면을 만듭니다. 서버가 내려준 이름·레벨·XP를 사용하고, 오래 걸린 이전 요청이 새 탭의 결과를 덮어쓰지 않도록 요청 순서를 확인합니다.

### 6. 복구 코드 안전하게 교체하기

로그인한 기기에서는 **새 복구 코드 준비**로 코드를 교체할 수 있습니다. `rotateRecovery()`는 버전 번호로 다른 기기에서 먼저 변경했는지 검사합니다. 같은 변경을 재확인하는 것은 허용하고 다른 변경이 덮어쓰는 것은 막습니다. 새 코드가 적용되면 이전 복구 코드와 옛 가입 요청으로는 접속할 수 없습니다. 이미 로그인한 다른 기기는 유지합니다.

모든 기기에서 로그아웃했고 복구 코드도 잃었다면 별명만으로 본인임을 확인할 수 없습니다. 이메일 인증이 없는 현재 구조의 한계입니다. 복구 코드는 공유하거나 공개 저장소에 올리지 마세요.

## 검증하는 오류 예시

`tests/identity.test.mjs`는 이름 동시 선점, 금지 입력, 응답 유실 후 가입 재확인, 요청 ID만으로 인증 시도, 두 기기의 중복 제출, 하트·XP·도전 진행 중복 방지, 복구 코드 동시 변경, 기존 중복 이름의 마이그레이션, 전체 조합 소진, 100위 밖 본인 표시를 확인합니다. 다른 테스트는 기존 실습·증거·보안 헤더·친구 방을 계속 확인합니다.

```bash
npm test
npm run build
```

읽은 뒤 연습할 주제는 SQL의 `UNIQUE`, `LEFT JOIN`, 트랜잭션, HTTP 세션, 해시, 비동기 요청 순서, 멱등성입니다. 순서대로 하나씩 이해하면 지금 계정과 랭킹이 왜 안정적으로 이어지는지 설명할 수 있습니다.

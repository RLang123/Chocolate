# TraceLab의 랭크·전문 챕터·용어 사전 코드

## 전체 흐름

```text
site/app.mjs: 요청 편집 → /api/labs/advanced
server/labs.mjs: 소유권 확인 → 격리된 처리 → 실행 증거 저장
/api/attempts/:id/answer: 현재 단계·실행 증거 확인
server/rank.mjs: 랭크 문제 완료 → 서버 점수 저장
```

사용자가 입력한 답변·점수·차단 여부를 그대로 기록하지 않습니다. 정답과 실습 단계는 서버가 검사하고, 전문 챕터의 실행 증거는 본인 시도와 현재 단계에 묶습니다.

## 랭크 모드

- 로그인한 사용자에게 하루 한 번(UTC 기준) 세 문제를 배정합니다.
- 제한 시간은 서버가 계산하는 30분입니다. 진행 중인 도전과 문제는 재개할 수 있습니다.
- 세 문제를 완료하면 최대 900점에서 오답당 25점을 빼서 저장합니다.
- Gold는 750점 이상, Silver는 450점 이상, 그 아래는 Bronze입니다. 기록한 점수에 대한 학습 등급입니다.
- 순위는 참가자별 최고 완료 점수, 동점이면 완료 소요 시간·완료 시각 순입니다.
- 미완료·만료 기록은 순위에 올리지 않습니다. 일반 실습 XP와 랭크 점수는 별도입니다.

`rank_runs`의 `(player_id, day)` 고유 조건은 같은 날 다른 도전으로 덮어쓰는 일을 막습니다. `attempts`의 랭크 도전·미션 고유 조건은 같은 문제를 다시 시작해 진행을 초기화하는 일을 막습니다. 완료는 현재 문제 순서에 맞을 때만 전진하고, 중복·동시 제출은 두 문제를 한꺼번에 완료시키지 않습니다.

핵심 파일: `server/rank.mjs`, `server/worker.mjs`, `migrations/0002_rank_and_labs.sql`.

## 전문 챕터 네 개

| 챕터 | 서버에서 처리하는 내용 | 수정 후 비교 |
| --- | --- | --- |
| HTTP·문서 권한 | 본인 실습에 속한 가상 문서를 D1에서 조회 | 다른 소유자의 문서는 403 |
| SQL·매개변수 | 가상 이름만 있는 읽기 전용 CTE를 실제 SQL로 조회 | OR 문자열을 값으로 처리해 결과가 달라짐 |
| 헤더·신뢰 경계 | 요청의 역할 표시와 서버의 실습 역할을 구별 | 헤더를 admin으로 바꿔도 403 |
| 로그인 로그·제한 | 반복 요청 기록을 저장하며 DB의 횟수로 판정 | 3회를 넘는 실습 요청에 429 |

요청 편집기는 HTTP 문법을 읽지만 실제 외부 네트워크로 그대로 전송하는 프록시는 아닙니다. `lab.local`과 지원한 경로·입력만 처리합니다. 임의 SQL·실제 계정 테이블·사용자의 실제 로그인 비밀번호·외부 서버는 실습 대상이 아닙니다. 실제 서비스와 비슷한 요청·응답·권한·SQL·로그 흐름을 격리해서 배우는 환경입니다.

`server/advanced.mjs`의 `parseLabRequest()`가 형식을 검사합니다. `server/labs.mjs`는 실습 소유권과 만료를 검사한 뒤 실행하고, `lab_evidence`에 증거를 저장합니다. `verifyAdvancedEvidence()`는 시도 ID·단계·요청·패치가 일치하는 증거만 받습니다. 클라이언트가 `blocked: true`를 적어도 정답이 되지 않습니다.

오프라인에서는 같은 원리 모형으로 연습합니다. 서버의 실행 증거나 랭크 점수로 간주하지 않습니다.

## 용어 사전과 검색 페이지

`server/content.mjs`에 60개 용어가 있습니다. 각 항목은 고유 주소, 한글·영문 이름, 분야, 쉬운 뜻, 비유와 예시를 가집니다.

```js
{
  slug: 'authorization',
  term: '인가·권한 검사',
  category: 'account',
  definition: '확인한 사용자가 특정 자료나 작업에 접근할 수 있는지 검사하는 과정입니다.'
}
```

`site/app.mjs`의 `renderGlossary()`는 이름·정의·예시에서 검색하고 분야로 거릅니다. `server/pages.mjs`는 같은 내용을 `/glossary/:slug`에 HTML로 렌더링합니다. Google과 JavaScript를 사용하지 않는 독자도 정의와 예시를 읽을 수 있습니다.

## 사이트 보안

- `server/security.mjs`: 본문을 읽는 도중 바이트 크기를 제한하고, 응답에 보안 헤더를 붙입니다.
- `scriptHashes()`: 실행할 인라인 스크립트마다 SHA-256 해시를 계산해 CSP에 넣습니다. 외부 Tailwind 스크립트와 스크립트의 `unsafe-inline` 허용을 제거했습니다.
- CSS는 기존 인라인 스타일을 사용하므로 `style-src 'unsafe-inline'`은 남아 있습니다. 스크립트 허용과는 구별됩니다.
- API는 요청 출처·JSON 형식·지원 메서드·계정 소유권·요청 횟수를 검사합니다.
- 로그인 세션은 HttpOnly·SameSite·HTTPS Secure 쿠키이며 30일입니다. 세션과 복구 코드는 서버에서 해시로 보관합니다.
- 프레임 차단, HTTPS HSTS, MIME 타입 검사와 권한 제한을 적용합니다.
- SQL과 실습 자료는 실제 사용자 자료와 분리합니다. 코드·쉘을 임의 실행하지 않습니다.
- 실습 편집기는 제공한 가상 쿠키·헤더만 받으며 실제 Authorization·세션 토큰 입력을 거부합니다. 만료한 세션과 7일 지난 만료 실습 증거를 정리합니다. 완료 XP·랭크 기록은 별도 테이블에 유지합니다.
- 배포 도구의 하위 `sharp` 취약점도 검사해 Wrangler 4.151.0으로 업데이트했습니다. 갱신한 의존성의 `npm audit` 결과는 0건입니다. 알려진 의존성 검사 결과이며 모든 보안 문제의 부재를 증명하지는 않습니다.

실행 증거는 실습 판정의 기준이며, 랭크는 학습용 모드입니다. 현재 닉네임 가입은 실명·대회 본인 인증이 아니므로 다중 계정과 자동 풀이를 완전히 배제하지 않습니다. 공인 침투 테스트 플랫폼이나 취약점이 절대로 없는 서비스라는 의미도 아닙니다.

## 빌드와 기존 기록

`scripts/build.mjs`는 모듈의 공통 규칙과 용어 데이터를 단일 HTML에 반영하고 Worker를 만듭니다. 새 프런트엔드 기능의 원본은 `site/app.mjs`이며 생성된 `TRACE_APP` 블록만 수정하면 다음 빌드에서 덮어씁니다.

`scripts/cloudflare-build.mjs`는 Wrangler 사용자 빌드입니다. Workers Builds에서 직접 `wrangler deploy`를 실행해도 업로드 전에 기존 DB를 확인하고 미적용 마이그레이션을 적용합니다. 코드 업로드 성공과 데이터베이스 준비는 별도라, 새 API만 게시되고 테이블은 빠지는 상황을 방지합니다.

기존 데이터베이스·Worker 이름과 브라우저 저장 키는 호환을 위해 유지합니다. 새 마이그레이션은 랭크와 실습 증거 테이블을 추가하며 기존 계정·점수·친구 방을 삭제하지 않습니다.

검증 명령: `npm test`, `npm run build`, `npm run cloudflare:check`. 테스트는 랭크 순서·위조 증거·소유권·동시 제출·보안 헤더·검색 페이지와 기존 기능을 확인합니다.

# 읽기 쉬운 문제 화면과 애니메이션

## 듀오링고에서 무엇을 분석했나요?

공식 자료를 읽고 TraceLab 실습에서 실제로 필요한 요소를 비교했습니다. 화면 크기와 간격, 색상 값은 TraceLab을 위한 설계입니다. 듀오링고의 현재 제품 전체를 복제했다는 의미는 아닙니다.

| 참고한 방식 | 기존 TraceLab의 문제 | 이번 적용 |
| --- | --- | --- |
| 짧은 상호작용과 선택적 설명 | 지시·배경·진행·코드·비교가 동시에 노출 | 질문 하나를 먼저 보고 긴 설명은 펼치기 |
| 학습에 집중하는 일관된 흐름 | 어두운 모달 프레임과 좌우 분할로 시선 분산 | 밝은 전체 화면, 가운데 문제, 고정된 하단 버튼 |
| 답을 고르고 확인하는 익숙한 순서 | 테두리 안내가 여러 곳에 나타나 다음 행동이 불분명 | 큰 선택지, 선택 상태, 준비됐을 때 확인 버튼 활성화 |
| 짧고 지지적인 결과 안내 | 성공·실패 설명과 코드 비교가 한꺼번에 등장 | 결과 한 문장, 체크 표시, 필요하면 자세한 이유 |
| 행동에 반응하는 캐릭터 | 화면 스캔과 여러 진입 효과가 읽는 내용과 경쟁 | Byte가 문제를 안내하고 선택·결과·실제 진행만 짧게 반응 |
| 단계를 작게 나누기 | 시작 전에 긴 안내부터 읽어야 함 | 목표 한 문장과 1~3개의 짧은 순서 |

출처:

- [Duolingo Method](https://blog.duolingo.com/duolingo-teaching-method/): 직접 해보는 연습, 선택적 힌트, 작은 학습 단위, 캐릭터와 격려.
- [Apple의 Duolingo 디자인 인터뷰](https://developer.apple.com/news/?id=jhkvppla): 따라가기 쉬운 UI와 정답에 반응하는 캐릭터 애니메이션.
- [Duolingo의 제품 원칙](https://blog.duolingo.com/product-principles/): 나이·언어·기술 숙련도가 다른 사용자를 고려하는 제품 설계.

TraceLab의 버건디는 선택과 기본 행동에, 카고색은 성공과 보조 설명에 사용합니다. 흰 배경과 검은색에 가까운 글자로 본문을 읽고, 정답·오답은 색상에 더해 문구와 아이콘으로 구별합니다.

## 주요 파일

| 파일 | 역할 |
| --- | --- |
| `site/lesson.mjs` | 문제 중심 구성, 짧은 질문, 도움말 접기, 확인 버튼, 결과와 키보드 조작 |
| `site/lesson.css` | 전체 화면, 글자 크기, 큰 선택지, 진행 막대, 하단 결과·버튼 영역 |
| `site/motion.mjs` | 공통 애니메이션 함수와 실제 실행 상태 연결 |
| `site/experience.mjs` | 실제 요청의 이동과 수정 전후 증거 비교 |
| `site/identity.mjs` | 서버 제출 재확인과 여러 기기의 계정 기록 |
| `scripts/build.mjs` | 마지막에 문제 화면 모듈·스타일을 넣어 HTML과 Worker 생성 |

`index.html`의 생성된 블록을 직접 바꾸지 말고 원본 모듈을 바꾼 뒤 `npm run build`를 실행하세요.

## 배울 코드 1: 정보를 한꺼번에 보여주지 않기

`disclosure()`는 HTML의 `<details>`와 `<summary>`를 만듭니다. 긴 안내와 처리 로그를 이 안으로 옮깁니다. 원래 DOM 노드를 이동하므로 기존 버튼의 이벤트·실행 증거·입력값 연결을 유지합니다. 코드 비교는 기본적으로 접혀 있고 원하는 사람이 직접 열 수 있습니다.

중요한 질문·예시·선택지는 접지 않습니다. 서버 권한·정답 조건·실습 단계도 변경하지 않습니다.

## 배울 코드 2: 답을 준비했는지와 정답인지는 다르기

`ready()`는 답안을 제출할 준비가 됐는지만 확인합니다. 선택지는 무엇이든 하나 고르면 확인할 수 있고, 비밀번호는 틀린 입력도 제출해 피드백을 받을 수 있습니다. 정답을 맞히기 전까지 버튼을 숨기는 방식이 아닙니다. 요청 실습에서는 실제 실행 후 제출할 수 있습니다.

`sync()`는 `submitting`으로 실제 서버 처리 중임을 표시하고 중복 클릭을 막습니다. 패킷·Snake 게임이 실행 중일 때는 원래의 실행 잠금을 지킵니다. 서버의 정답 검증과 점수 저장은 계속 기존 코드가 담당합니다.

## 배울 코드 3: 진짜 진행에만 애니메이션 주기

진행 막대는 현재 단계와 `passed`로 계산합니다. 정답 확인 전에는 진행한 것처럼 채우지 않습니다. 결과 아이콘은 `response()`가 받은 실제 정오답에 반응합니다. 요청 이동은 기존 실행 Promise와 실제 응답을 사용합니다.

Web Animations API의 예:

```js
labAnimate(icon, [
  { transform: 'scale(.6) rotate(-12deg)' },
  { transform: 'scale(1.1) rotate(4deg)', offset: .7 },
  { transform: 'scale(1)' }
], { duration: 300 });
```

한 번의 짧은 반응입니다. 다음 행동을 애니메이션이 끝날 때까지 막거나 응답을 일부러 늦추지 않습니다. 운영체제의 움직임 줄이기 설정이면 애니메이션을 생략하고 상태·글자·아이콘을 그대로 보여줍니다.

## 조작과 접근성

- 큰 선택지 전체를 눌러 답합니다. 선택 상태는 `aria-pressed`로도 전달합니다.
- 숫자 1~9로 선택하고 Enter로 확인하거나 계속할 수 있습니다. 입력칸·게임 키보드 조작·버튼 자체의 기본 동작을 방해하지 않습니다.
- 문제를 바꾸면 새 질문에 초점을 둡니다. Escape로 닫으면 기존 화면으로 돌아갑니다.
- 진행 막대는 완료 단계 수를 스크린 리더에 제공합니다.
- 모바일에서도 하단 확인 버튼은 남고 긴 문제 본문만 스크롤합니다.
- 정답에 대한 짧은 설명과 자세한 이유는 분리하며, 복습 완료 시 이미 받은 XP를 다시 지급했다고 표시하지 않습니다.

검증은 `npm test`, `npm run build`와 실제 브라우저에서 수행합니다. 화면 검증에서는 31개 실습의 데스크톱·모바일 배치, 선택·입력·게임, 정오답, 전문 요청 실습, 랭크의 다음 문제, 복구 코드로 다른 기기에서 이어하기를 확인합니다.

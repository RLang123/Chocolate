# 내 사이트로 배우는 웹 개발과 보안

이 문서는 HackLingo의 코드를 읽고 직접 고쳐보고 싶은 처음 배우는 사람을 위한 학습서입니다. 코딩 경험이 없어도 앞에서부터 따라갈 수 있도록 만들었습니다.

목표는 코드를 외우는 것이 아니라 **내가 바꾼 코드가 화면과 동작에 어떤 영향을 주는지 설명할 수 있게 되는 것**입니다. 한 번에 다 읽기보다 한 장을 읽고 작은 수정 하나를 해보세요.

코드가 길게 한 줄로 쓰여 있어도 당황하지 않아도 됩니다. 설명 속 예제는 읽기 쉽게 줄을 나누었고, 기능을 줄여 보여주는 예제에는 별도로 표시했습니다. 줄 번호는 수정할 때마다 바뀌므로 파일을 연 다음 함수 이름을 검색해서 찾아보세요.

## 1. 프로젝트 지도

웹사이트의 앞부분은 브라우저가 보여주고, 뒷부분은 서버가 요청을 처리합니다. 프런트엔드는 화면과 사용자 조작을, 백엔드는 계정·검증·공유 데이터 처리를 담당합니다.

| 파일 | 역할 | 먼저 찾아볼 것 |
| --- | --- | --- |
| [index.html](../index.html) | 화면 구조, 디자인, 브라우저 동작 | `data-mission`, `renderLesson` |
| [server/rules.mjs](../server/rules.mjs) | 정답과 게임 규칙 | `validateAnswer` |

처음에는 `index.html`을 중심으로 읽으세요. SQL과 게임 검증은 화면 동작이 익숙해진 뒤 읽어도 됩니다.

### 개발 화면 열기

Node.js 24 이상에서 프로젝트 폴더의 터미널을 엽니다. 처음 설치할 때는 다음 명령을 실행합니다.

```bash
npm ci
npm run dev
```

`npm ci`는 프로젝트에 기록된 버전대로 필요한 패키지를 설치합니다. 이미 설치되어 있다면 매번 다시 실행할 필요는 없습니다. `npm run dev`는 `package.json`의 `dev` 명령을 실행합니다.

브라우저에서 `http://localhost:8787`을 엽니다. Codespaces에서는 Ports 탭의 8787 포트를 브라우저로 여세요. 이 개발 화면에서 수정하고 확인한 뒤 배포할 수 있습니다. 소스 파일을 저장하는 것만으로 공개 사이트가 바뀌지는 않습니다.

## 2. HTML — 무엇을 보여줄까?

HTML은 화면에 제목·글·입력창·버튼을 놓는 언어입니다. 태그는 각 요소의 종류를 표시합니다.

실제 첫 실습 버튼입니다.

```html
<button class="btn" data-mission="0">첫 실습 시작하기 →</button>
```

| 부분 | 뜻 |
| --- | --- |
| `<button>` | 버튼 요소의 시작 |
| `class="btn"` | `btn`이라는 디자인 규칙을 적용 |
| `data-mission="0"` | JavaScript가 읽을 실습 번호 |
| `첫 실습 시작하기 →` | 사용자가 읽는 글 |
| `</button>` | 버튼 요소의 끝 |

`class`는 여러 요소에 같은 디자인을 붙일 때 사용합니다. `id`는 문서 안에서 특정 요소 하나를 찾을 때 사용하며 중복하지 않아야 합니다. 이 사이트의 정답 확인 버튼에는 `id="check"`가 있습니다.

**작은 연습:** 버튼의 글을 `비밀번호 연습 시작하기 →`로 바꾸고 저장한 뒤 새로고침하세요. 글만 바꿨다면 열리는 실습은 그대로입니다. 동작을 결정하는 값은 `data-mission`이기 때문입니다.

HTML의 버튼이나 입력창을 적절한 요소로 만들면 키보드로도 사용할 수 있습니다. 겉모습을 버튼처럼 꾸민 `div`보다 실제 `button`을 쓰는 이유 중 하나입니다.

## 3. CSS — 어떻게 보여줄까?

CSS는 색상·글자 크기·간격·배치를 정합니다. 기본 형태는 다음과 같습니다.

```css
.logo-mark {
  background: var(--brand);
}
```

`.logo-mark`는 `class="logo-mark"`가 붙은 요소를 고르는 **선택자**입니다. 중괄호 안의 `background`는 바꿀 속성이고, 오른쪽은 속성의 값입니다.

### 버건디 색상과 CSS 변수

프로젝트에서 사용하는 설정입니다.

```css
:root {
  --brand: #7b263f;
  --brand-soft: #f7edf0;
}
```

`#7b263f`는 빨강·초록·파랑의 양을 16진수로 표현한 색상입니다. `--brand`는 이름을 붙인 CSS 변수이고, `var(--brand)`로 그 값을 가져옵니다. `--brand-soft`는 선택 표시와 안내 상자의 연한 배경입니다.

기존 코드에는 색상을 직접 적은 부분도 있습니다. 따라서 `--brand`만 바꿔도 모든 강조 색이 자동으로 바뀌는 것은 아닙니다. 같은 색을 여러 곳에 쓰려면 점차 변수로 모으는 방식이 관리하기 쉽습니다.

### 간격과 크기

| 속성 | 뜻 | 기억할 예 |
| --- | --- | --- |
| `padding` | 요소의 안쪽 여백 | 상자와 글 사이 |
| `margin` | 요소의 바깥쪽 여백 | 상자와 다음 상자 사이 |
| `gap` | 함께 배치한 항목 사이의 간격 | 카드끼리의 거리 |
| `border` | 테두리 | `1px solid` |
| `border-radius` | 모서리 둥글기 | `8px` |
| `line-height` | 줄 사이 높이 | 긴 설명의 가독성 |

**작은 연습:** `.step-instructions`의 여백이나 테두리를 바꾸고 실제 실습을 열어보세요. 한 속성씩 바꾸면 무엇 때문에 화면이 달라졌는지 알기 쉽습니다.

### 모바일에서도 읽을 수 있게 만들기

CSS의 `@media`는 화면 조건에 따라 다른 규칙을 적용합니다.

```css
@media(max-width:480px) {
  .lesson-orientation,
  .step-instructions,
  .next-lesson {
    padding: 16px;
  }
}
```

화면 너비가 480px 이하일 때 이 세 종류의 상자에 안쪽 여백 16px을 적용합니다. 큰 화면에 보기 좋은 배치라도 작은 화면에서는 글자가 넘치거나 버튼이 가려질 수 있어 두 크기를 모두 확인해야 합니다.

## 4. JavaScript — 값과 동작을 표현하기

JavaScript는 버튼 클릭을 처리하고 화면을 바꿉니다. 먼저 아래 여섯 가지를 익히면 프로젝트의 주요 코드를 읽기 쉬워집니다.

### ① 변수와 값

아래는 문법을 설명하기 위한 독립 예제입니다.

```js
const title = '비밀번호 금고';
let step = 0;
step = step + 1;
```

변수는 값에 붙이는 이름입니다. `const`는 그 이름에 다른 값을 다시 대입하지 않을 때, `let`은 다시 대입할 때 사용합니다. 문자열은 글자, 숫자는 수, `true`와 `false`는 참과 거짓입니다.

`const`에 객체나 배열을 담아도 그 안의 내용까지 자동으로 고정되지는 않습니다. 예를 들어 `const completed = []`를 선언한 뒤 `completed.push(0)`으로 항목을 추가할 수 있습니다.

### ② 배열과 객체

아래도 문법 연습 예제입니다.

```js
const completed = [0, 1, 13];
const guide = {
  goal: '가짜 메일을 구별해요.',
  steps: ['주소 확인', '재촉하는 말 확인', '링크 확인']
};

console.log(completed[0]); // 0
console.log(guide.goal);   // 가짜 메일을 구별해요.
console.log(guide.steps[1]); // 재촉하는 말 확인
```

배열은 순서가 있는 목록이고, 객체는 이름과 값을 묶은 자료입니다. 배열의 첫 칸은 0번입니다. 그래서 `steps[1]`은 두 번째 설명입니다.

이 프로젝트의 `missions`는 실습 목록, `lessonGuides`는 설명 목록, `state`는 현재 학습 기록을 담은 객체입니다.

### ③ 조건문

```js
const completed = [0, 1, 13];

if (completed.includes(0)) {
  console.log('비밀번호 실습을 완료했어요.');
} else {
  console.log('비밀번호 실습부터 해보세요.');
}
```

`if`는 조건이 참일 때 실행하고, `else`는 그렇지 않을 때 실행합니다. `includes(0)`은 목록 안에 0이 있는지 확인합니다.

`=`는 대입, `===`는 엄격한 값 비교입니다. `!`는 참과 거짓을 뒤집고, `&&`는 두 조건이 모두 참이어야 한다는 뜻입니다. 실제 추천 코드에서 자주 만나는 문법입니다.

### ④ 함수

실제 코드입니다.

```js
function learningGroup(id) {
  return learningGroups.find(g => g.missions.includes(id));
}
```

함수는 이름을 붙여 다시 사용할 수 있는 동작입니다. `id`는 함수가 받을 입력이고, `return`은 처리 결과를 돌려줍니다. `learningGroup(13)`은 13번 실습이 속한 그룹 객체를 찾습니다.

`g => ...`는 짧게 쓴 함수입니다. 여기서는 그룹 하나를 받아 그 그룹에 해당 실습 ID가 있는지 확인합니다.

### ⑤ 목록 다루기

| 메서드 | 하는 일 | 이 사이트에서 쓰는 곳 |
| --- | --- | --- |
| `find()` | 조건에 맞는 첫 항목 찾기 | 다음 실습, 실습 그룹 |
| `filter()` | 조건에 맞는 항목들 남기기 | 검색·분야 필터 |
| `map()` | 각 항목을 새 값으로 바꾸기 | 실습 데이터를 카드 글로 변환 |
| `join()` | 문자열 목록을 하나로 연결 | 카드 HTML 합치기 |
| `sort()` | 목록 순서 바꾸기 | 학습 순서 정렬 |

독립적으로 실행할 수 있는 예제입니다.

```js
const lessons = [
  { id: 0, title: '비밀번호', category: '계정' },
  { id: 1, title: '피싱 메일', category: '사기' },
  { id: 7, title: '추가 인증', category: '계정' }
];

const accountTitles = lessons
  .filter(lesson => lesson.category === '계정')
  .map(lesson => lesson.title);

console.log(accountTitles); // ['비밀번호', '추가 인증']
```

### ⑥ 템플릿 문자열

```js
const currentStep = 0;
const totalSteps = 2;
const label = `지금 할 일 · ${currentStep + 1}/${totalSteps}`;
console.log(label); // 지금 할 일 · 1/2
```

백틱으로 감싼 문자열 안에서 `${...}`에 계산 결과를 넣을 수 있습니다. 현재 단계 번호나 실습 제목을 HTML에 넣을 때 사용합니다.

## 5. 버튼을 누르면 일어나는 일

이 프로젝트의 가장 중요한 읽기 순서입니다.

```text
버튼 클릭
  → 어떤 실습인지 읽기
  → openMission(id)
  → renderLesson(): 개요 보여주기
  → beginChallenge(): 문제 시작하기
  → evaluateAnswer(): 답 검사하기
  → response(): 설명 보여주기
  → 다음 단계 또는 completeMission()
  → nextLessonMarkup(): 다음 실습 추천하기
```

### DOM과 요소 찾기

DOM은 브라우저가 HTML의 요소들을 다룰 수 있도록 만든 구조입니다. 다음은 실제 코드의 `$` 함수를 읽기 쉽게 풀어 쓴 것입니다.

```js
const $ = selector => document.querySelector(selector);
```

`document.querySelector('#check')`는 `id="check"`인 요소를 찾습니다. 같은 일을 `$('#check')`라고 짧게 적을 수 있습니다. 여기의 `$`는 이 프로젝트에서 만든 함수이며 별도의 라이브러리를 뜻하지 않습니다.

### 이벤트와 클릭 처리

실제 클릭 처리기의 실습 관련 부분만 풀어 쓴 예제입니다.

```js
document.addEventListener('click', event => {
  const button = event.target.closest('[data-mission]');
  if (button) {
    openMission(Number(button.dataset.mission));
  }
});
```

이벤트는 클릭·키 입력·입력값 변경처럼 발생한 일입니다. `addEventListener()`는 그 일이 생겼을 때 실행할 함수를 등록합니다.

`event.target`은 실제로 누른 요소입니다. 버튼 안의 글이나 아이콘을 눌렀을 수도 있으므로 `closest()`로 `data-mission`이 붙은 가장 가까운 요소를 찾습니다. `dataset.mission`은 HTML 속성의 값을 읽습니다. HTML에서 읽은 값은 문자열이므로 `Number()`로 숫자로 바꿉니다. 실제 구현은 `+m.dataset.mission`으로 같은 변환을 합니다.

페이지 전체에서 클릭을 받아 처리하므로 나중에 새로 만든 실습 카드에도 같은 처리기를 사용할 수 있습니다. 이런 방식을 이벤트 위임이라고 부릅니다.

**읽어볼 코드:** `openMission()`은 실습을 찾고 단계와 상태를 초기화합니다. `renderLesson()`은 그 상태에 맞는 화면을 만듭니다. 화면을 만드는 일과 상태를 바꾸는 일을 구별해서 읽어보세요.

## 6. 실습 설명과 검색을 관리하는 코드

### 설명은 `lessonGuides`

실제 데이터 형태를 줄여 보여주는 예제입니다.

```js
const guide = {
  goal: '긴 비밀번호와 추가 인증이 계정을 지키는 방법을 알아요.',
  steps: [
    '연습용 비밀번호를 입력하고 다섯 조건이 채워지는지 봐요.',
    '비밀번호를 반복해서 맞혀보는 시도를 어떻게 막을지 생각해요.'
  ]
};
```

`lessonGuides[0]`은 첫 실습의 설명입니다. `lessonOrientation()`은 시작할 때 전체 순서를 보여주고, `stepInstructions()`는 현재 단계에서 할 일만 보여줍니다. 설명을 바꿀 때에는 실제 단계 수와 버튼 이름도 맞아야 합니다.

새 설명이 적용되는 곳은 여러 군데입니다. `goal`은 실습 카드·개요·추천에, `steps`는 개요와 각 문제 단계에 쓰입니다. 데이터를 모아두면 여러 화면의 문구를 함께 관리할 수 있습니다.

### 검색은 `renderMissions()`

검색의 흐름은 다음과 같습니다.

```text
실습 목록
  → 분야 조건 확인
  → 학습 단계 조건 확인
  → 검색어가 제목·설명 등에 포함되는지 확인
  → 학습 순서로 정렬
  → 카드 HTML 만들기
```

`filter()`는 데이터베이스를 지우지 않고 화면에 표시할 항목만 골라냅니다. 검색해도 원래 실습은 남아 있습니다.

### ID와 목록 위치는 구별하기

`mission.id`는 실습을 식별하는 번호입니다. 배열에서 몇 번째로 보이는지와는 다릅니다. 화면에서 13번 게임 실습을 먼저 보여줘도 ID는 그대로 13입니다.

이 사이트는 설명 배열 `lessonGuides`를 실습 ID로 읽고, 실제 실습 객체는 `missions.find(m => m.id === id)`로 찾습니다. 정렬을 바꾼 뒤 `missions[id]`가 반드시 해당 ID라고 가정하면 잘못된 실습을 고를 수 있습니다.

**작은 연습:** `learningOrder`를 찾아 첫 세 값이 `0, 1, 13`인 이유를 설명해보세요. 추천 순서만 바꾸는 일과 서버가 사용하는 실습 ID를 바꾸는 일은 별개입니다.

## 7. 상태와 다음 실습

상태는 프로그램이 현재 기억하고 있는 정보입니다.

| 이름 | 역할 | 예 |
| --- | --- | --- |
| `phase` | 개요·문제·완료 중 어느 화면인지 | `'brief'`, `'challenge'`, `'result'` |
| `step` | 문제의 현재 단계 | 0, 1, 2 |
| `selection` | 사용자가 고른 답 | 선택지 번호 |
| `passed` | 현재 단계를 맞혔는지 | `true`, `false` |
| `state.completed` | 완료한 실습 ID 목록 | `[0, 1, 13]` |
| `online` | 공유 계정으로 서버 판정을 사용하는지 | `true`, `false` |

`online`은 단순히 인터넷이 연결되었다는 뜻이 아닙니다. 이 프로젝트에서는 공유 계정으로 참가해 서버의 기록을 사용하는 상태를 뜻합니다.

추천 코드의 핵심을 실제 구현에서 발췌했습니다.

```js
const next = learningOrder.find(id =>
  id !== mission.id && !state.completed.includes(id)
);
```

순서대로 목록을 보면서 현재 실습이 아니고, 아직 완료하지 않은 첫 ID를 찾습니다. 해당 항목이 없으면 `next`는 `undefined`가 되고 전체 완료 안내를 보여줍니다. “실습 번호에 1을 더하기”와 달리 이미 끝낸 실습을 건너뛸 수 있습니다.

**직접 생각해보기:** 순서가 `[0, 1, 13, 7]`이고 완료 목록이 `[0, 1]`, 현재 실습이 1이라면 다음 추천은 무엇일까요? 답은 13입니다.

## 8. 서버, API, 데이터베이스

서버는 브라우저의 요청을 받아 처리합니다. API는 브라우저와 서버가 어떤 주소로 어떤 정보를 주고받을지 정한 통로입니다.

### 요청과 응답

이 사이트에서 사용하는 예입니다.

| 요청 | 용도 |
| --- | --- |
| `GET /api/me` | 현재 로그인한 사용자와 학습 기록 읽기 |
| `GET /api/leaderboard` | 실제 참가자 순위 읽기 |
| `POST /api/attempts/start` | 새 실습 시도 만들기 |
| `POST /api/attempts/:id/answer` | 해당 실습의 단계 답 제출 |

`:id`는 실제 요청에서 실습 시도의 ID로 바뀝니다. 실습 종류의 ID인 `mission.id`와 이번 도전 기록의 ID인 `pendingAttempt.id`는 서로 다릅니다.

### JSON

JSON은 이름과 값을 묶어 주고받는 자료 형식입니다. 이름과 문자열은 큰따옴표로 씁니다.

```json
{
  "step": 1,
  "answer": 0
}
```

이 예는 두 번째 단계에서 첫 선택지를 골랐다는 뜻입니다. 실제 답의 형태는 실습마다 다릅니다. 문자열, 선택지 번호, 이동 기록 등을 제출할 수 있습니다.

### `async`와 `await`

실제 API 함수의 핵심만 줄여 보여주는 예제입니다.

```js
async function requestData(path) {
  const response = await fetch(path);
  if (!response.ok) {
    throw new Error('요청을 처리하지 못했어요.');
  }
  return await response.json();
}
```

네트워크 응답은 즉시 도착하지 않습니다. `async` 함수는 비동기 결과를 돌려주고, `await`는 결과가 준비된 뒤 다음 코드를 실행하게 합니다. 응답을 기다리는 동안 브라우저 전체를 멈추는 방식은 아닙니다.

실제 `api()` 함수는 쓰기 요청에 `POST`와 JSON 본문을 설정하고, 같은 출처의 쿠키를 함께 보내며 오류 응답도 처리합니다. 위 예제는 읽기 요청과 대기 흐름을 이해하기 위한 축약본입니다.

### 중복 클릭과 늦게 도착한 응답

`submitAnswer()`를 찾아 다음 세 부분을 읽어보세요.

1. `submitting=true`와 버튼 비활성화: 답을 보내는 중에 다시 누르는 일을 줄입니다.
2. `lessonGeneration`: 요청 중 창을 닫거나 다른 실습을 열었을 때 오래된 응답이 새 실습 화면을 바꾸지 않게 구별합니다.
3. `try / catch / finally`: 성공 처리, 오류 안내, 요청이 끝났을 때의 정리를 나눕니다.

버튼을 숨기거나 비활성화하는 것은 사용자 조작을 돕는 기능입니다. 서버는 별도로 단계와 중복 보상을 검사합니다.

### 기록을 저장하는 세 가지 위치

| 위치 | 수명과 범위 | 프로젝트에서의 용도 |
| --- | --- | --- |
| JavaScript 변수 | 현재 페이지 실행 중 | 현재 단계, 선택한 답 |
| `localStorage` | 해당 브라우저·출처에 저장 | 혼자 연습 기록, 효과음 설정 |
| 서버의 D1/SQLite | 공유 계정의 지속 기록 | 완료·보상·계정·친구 방 |

`persist()`는 혼자 연습 기록을 `JSON.stringify(state)`로 문자열로 바꿔 저장합니다. 읽을 때에는 `JSON.parse()`로 다시 객체로 만듭니다. 로컬 저장소는 사용자가 변경할 수 있고 다른 기기와 자동 공유되지 않습니다.

데이터베이스는 여러 기록을 표 형태로 보관합니다. `players`는 계정, `attempts`는 실습 도전, `completions`는 완료 보상을 저장합니다.

다음은 실제 완료 테이블에서 가져온 제약입니다.

```sql
PRIMARY KEY (player_id, mission_id, day)
```

이 세 값의 조합은 중복될 수 없습니다. 서버는 같은 조합을 다시 넣을 때 `ON CONFLICT ... DO NOTHING`을 사용합니다. 그래서 한 사용자의 같은 실습·같은 UTC 날짜 보상을 중복 저장하지 않습니다.

## 9. 이 프로젝트에서 배울 보안 코드

여기서는 실제 코드의 방어 원리를 이해하는 데 집중합니다. 화면의 설명과 공유 서버의 검증을 연결해서 읽어보세요.

### 글을 글로 표시하기

다음은 비교를 위한 짧은 예제입니다.

```js
const message = '<b>안녕하세요</b>';
const output = document.createElement('p');
output.textContent = message;
```

`textContent`는 `<b>`를 포함한 내용을 글로 취급합니다. `innerHTML`은 HTML로 해석하므로 같은 문자열에서 태그의 의미가 달라집니다. 사용자 글을 HTML로 바로 넣으면 의도하지 않은 요소나 실행 가능한 내용을 만들 수 있습니다.

이 사이트는 개발자가 만든 카드 구조를 HTML 문자열로 만들고, 동적으로 끼워 넣는 글에는 `escapeHtml()`을 사용합니다. 해당 함수는 `&`, `<`, `>`, 큰따옴표를 HTML에서 다른 의미로 해석되지 않도록 바꿉니다.

`escapeHtml()`이 모든 종류의 보안 검사를 대신하지는 않습니다. URL이 안전한지, 사용자가 자료를 볼 권한이 있는지는 다른 검사입니다. 일반 글 하나를 표시하는 용도라면 `textContent`가 이해하기 쉽습니다.

### SQL의 명령과 값을 나누기

실제 서버의 데이터베이스 도우미입니다.

```js
const query = (db, sql, ...args) => db.prepare(sql).bind(...args);
```

`...args`는 여러 인수를 모으거나 펼치는 문법입니다. 여기서는 SQL에 넣을 값을 받습니다. `prepare()`는 명령을 준비하고, `bind()`는 값을 연결합니다.

예를 들어 `SELECT ... WHERE id = ?`의 `?` 자리에 ID를 값으로 연결합니다. 입력을 SQL 명령 문자열에 직접 이어 붙이는 방식과 구별됩니다. 매개변수를 쓴다고 읽기 권한까지 자동으로 생기는 것은 아니므로 권한 검사도 필요합니다.

### 인증과 권한은 다른 질문

| 개념 | 질문 | 실제 코드 |
| --- | --- | --- |
| 인증 | 이 요청은 어느 계정의 요청인가? | `playerFor()` |
| 권한 검사 | 그 계정이 이 자료나 동작에 접근해도 되는가? | 실습 소유자 조건, 방장 조건 |

`playerFor()`는 쿠키에 담긴 세션 토큰을 확인해 사용자를 찾습니다. 답변 처리기는 이어서 실습 ID와 `player_id`를 함께 조회합니다. 로그인한 사용자라도 다른 사용자의 실습 답변을 제출하게 해서는 안 되기 때문입니다.

방 시작도 화면에서 방장 버튼만 보여주는 것으로 끝내지 않습니다. 서버가 방의 `owner_id`와 현재 사용자 ID가 같은지 확인합니다.

### 점수와 게임 기록 검증

브라우저가 “999점이에요”라고 보내도 서버는 그 숫자만 믿지 않습니다. `validateAnswer()`는 실습의 답을 검사하고, Snake와 패킷 게임은 서버의 시드와 기록으로 규칙에 맞는 결과인지 확인합니다.

시드는 게임의 초기 상황을 만드는 데 사용하는 값입니다. 같은 시드와 같은 규칙으로 기록을 다시 계산할 수 있어 실제 가능한 움직임이었는지 비교하는 데 사용합니다.

이 사이트의 Snake 명령 입력은 허용된 명령 형태를 해석하는 실습입니다. 임의 JavaScript를 `eval()`로 실행하는 창이 아닙니다. 정해진 함수 교체 동작을 통해 원리를 배우도록 되어 있습니다.

### 해시와 암호화 구별하기

서버는 세션 토큰과 복구 코드의 SHA-256 해시를 저장합니다. 해시는 입력을 일정한 형태의 요약값으로 바꾸고 일치 여부를 비교하는 데 쓰입니다. 암호화는 키를 사용해 원문을 다시 복구할 수 있도록 변환하는 방식입니다.

이 프로젝트의 무작위 복구 코드 해시 저장 방식을 실제 사용자 비밀번호 저장에 그대로 복사해서는 안 됩니다. 비밀번호 저장은 별도의 전용 해싱 방식과 설계가 필요한 주제이므로 인증 흐름을 이해한 뒤 따로 학습하세요.

## 10. 디버깅, Git, 확인 습관

디버깅은 예상과 다른 동작의 원인을 찾는 일입니다. 한 번에 여러 곳을 고치기보다 **예상한 결과 → 실제 결과 → 두 결과가 달라진 지점**을 확인해보세요.

### 브라우저 개발자 도구에서 볼 것

| 탭 | 확인할 것 |
| --- | --- |
| Elements | 버튼과 안내 상자가 실제로 생겼는지, 적용된 CSS |
| Console | JavaScript 오류와 실험 출력 |
| Network | 요청 주소·HTTP 상태·서버 응답 |
| Application/Storage | 로컬 저장 기록과 쿠키 |

Console에는 실행할 코드를 입력할 수 있습니다. 이 문서의 독립 문법 예제는 로컬 개발 페이지에서 실행해보세요. 공유 계정의 점수를 바꾸는 대신 배열·함수의 출력부터 확인하면 됩니다.

### 자주 만나는 문제

| 현상 | 먼저 확인할 곳 |
| --- | --- |
| 글을 고쳤는데 화면이 그대로 | 파일 저장, 새로고침, 로컬/공개 주소 구별 |
| 버튼을 눌러도 반응이 없음 | Console 오류, `data-mission` 값, 클릭 처리기 |
| `undefined`가 표시됨 | 배열 위치, 객체 속성 이름, 단계 수 |
| 모바일에서 긴 주소가 넘침 | `min-width`, 줄바꿈, 부모 요소 폭 |
| 요청이 실패함 | Network의 상태 코드와 응답 메시지 |
| 코드는 맞는데 게임 판정 실패 | 현재 단계, 실행 기록, 최소 소요 시간 등 검증 조건 |

HTTP 상태에서 200대는 성공, 400대는 요청이나 접근 조건의 문제, 500대는 서버 처리 문제를 나타냅니다. 숫자만 보지 말고 응답 메시지도 함께 읽으세요.

### Git은 수정 이력 관리

먼저 읽기 명령 두 가지를 익히세요.

```bash
git status --short
git diff
```

`status`는 수정된 파일을, `diff`는 이전 상태와 달라진 내용을 보여줍니다. 내가 바꾸려던 부분만 달라졌는지 확인하는 습관을 들이세요. 커밋은 확인한 변경을 이력에 기록하는 일이고, push는 그 기록을 원격 저장소에 보내는 일입니다.

### 테스트와 빌드

```bash
npm test
npm run build
```

테스트는 서버의 계정·권한·정답·보상이 예상대로 동작하는지 확인합니다. 빌드는 공통 규칙을 HTML에 반영하고 `dist/`에 배포용 파일을 만듭니다. 화면의 가독성은 테스트만으로 알기 어려우므로 브라우저에서도 확인합니다.

**수정할 원본:** 화면은 `index.html`, 공유 정답 규칙은 `server/rules.mjs`입니다. `dist/`는 생성 결과이고 `index.html` 안의 SHARED_RULES 구역도 빌드가 반영하는 복사본입니다. 규칙을 바꿀 때에는 원본을 수정하고 다시 빌드하세요.

## 11. 직접 해볼 연습

아래 연습은 순서대로 진행하세요. 각 연습이 끝나면 무엇을 바꿨고 어디에 영향을 주었는지 한 문장으로 적어보세요.

### 연습 1 — 첫 버튼의 글 바꾸기

`data-mission="0"`인 첫 버튼을 찾아 글만 바꿉니다. 새로고침 후 바뀐 글을 확인하고 여전히 비밀번호 실습이 열리는지 봅니다.

**성공 기준:** 글은 달라지고 열리는 실습은 그대로입니다.

### 연습 2 — 안내 상자에 여백 주기

`.step-instructions`의 안쪽 여백을 바꿉니다. PC와 작은 모바일 화면에서 실습을 열어 비교합니다.

**성공 기준:** 글이 잘 읽히고 정답 확인 버튼을 사용할 수 있습니다.

### 연습 3 — 첫 실습의 설명 바꾸기

`lessonGuides[0]`의 `goal`을 자기 말로 바꿉니다. 단계 수는 유지합니다. 카드와 실습 개요에 새 목표가 나타나는지 확인합니다.

**성공 기준:** 같은 목표가 여러 화면에 일관되게 나타납니다.

### 연습 4 — 검색 코드 따라 읽기

`renderMissions()`를 찾아 `filter`, `sort`, `map`, `join` 부분을 구별합니다. ‘계정’ 분야와 ‘기초’ 단계를 동시에 선택하고 제목을 검색해보세요.

**성공 기준:** 표시 항목이 줄어드는 이유를 설명하고 검색을 지우면 다시 나타나는 것을 확인합니다.

### 연습 5 — 추천을 독립 코드로 만들기

아래 코드를 로컬 개발 페이지 Console이나 별도 연습 파일에서 실행합니다.

```js
const order = [0, 1, 13, 7];
const completed = [0, 1];
const next = order.find(id => !completed.includes(id));
console.log(next); // 13
```

완료 목록에 13을 추가해 결과가 7이 되는지 봅니다. 모든 ID를 추가하면 `undefined`가 됩니다.

**성공 기준:** 이미 끝낸 실습을 건너뛰는 조건을 스스로 설명합니다.

### 연습 6 — 답변 요청 관찰하기

로컬 서버에서 닉네임으로 참가한 뒤 Network 탭을 열고 실습 답을 확인합니다. `/api/attempts/.../answer` 요청에서 단계·답과 서버 응답을 읽습니다. 복구 코드나 쿠키를 복사해 공유할 필요는 없습니다.

**성공 기준:** 화면의 정답 확인 버튼과 서버 답변 요청을 연결해 설명합니다.

| 먼저 | CSS Flexbox·Grid·반응형 배치 | PC·모바일 화면을 직접 정돈함 |

| 그다음 | HTTP·JSON·비동기 처리 | 서버 연결과 오류를 직접 추적함 |
| 그다음 | SQL·기본키·데이터 무결성 | 계정·기록·중복 보상의 구조를 이해함 |

이 프로젝트로는 JavaScript를 먼저 배우는 것이 가장 바로 도움이 됩니다. 다른 언어를 추가하기보다 현재 버튼 하나를 끝까지 설명할 수 있게 된 다음 학습 범위를 넓혀보세요.

### 이해했는지 스스로 확인하기

- [ ] `class`, `id`, `data-mission`의 차이를 설명할 수 있다.
- [ ] HTML·CSS·JavaScript가 각각 맡는 일을 설명할 수 있다.
- [ ] 배열의 첫 칸이 0이고 실습 ID와 표시 순서는 다르다는 것을 안다.
- [ ] `find`, `filter`, `map`을 작은 예제로 사용해봤다.
- [ ] 클릭에서 실습 창이 열리기까지 코드 흐름을 따라갔다.
- [ ] 변수·로컬 저장소·서버 데이터베이스의 차이를 안다.
- [ ] 인증과 권한, 화면 점수와 서버 판정을 구별할 수 있다.
- [ ] 수정한 뒤 개발 화면과 `git diff`를 확인할 수 있다.

## 13. 실습 안내와 이어하기 코드를 읽기

QR 주소를 조사하거나 사진을 가리고, 앱 권한을 끄는 기초 실습에도 조작 강조가 있습니다. SQL·암호·로봇·역분석·응용 시나리오는 선택과 실행 상태에 따라 다음 조작이 달라집니다. 입력 이벤트와 비동기 실행 완료 시점에 `updateCoach()`를 호출하는 이유는 화면 안내가 현재 상태를 따라가게 하기 위해서입니다.

Cloudflare 연결 오류와 이번에 추가한 검증 코드는 별도의 [배포 학습 안내](CLOUDFLARE_GUIDE.md)에 정리했습니다. 로컬 파일을 고치는 것, GitHub에 커밋을 올리는 것, Cloudflare가 그 커밋을 빌드하는 것은 서로 다른 단계입니다.

이 장은 앞에서 배운 배열·조건문·화면 변경·서버 요청을 하나의 기능으로 연결하는 연습입니다.

### 힌트를 점점 구체적으로 보여주기

`guidedHints`는 실습 ID → 문제 단계 → 힌트 순서로 구성된 자료입니다. 첫 힌트는 관찰할 곳을 알려주고, 두 번째는 예시를 주며, 마지막은 조작 순서를 구체적으로 안내합니다.

```text
guidedHints[실습 ID][현재 단계][힌트 번호]
```

`hintLevel`은 현재 힌트 번호입니다. `renderHint()`가 해당 설명을 보여주고, ‘더 구체적인 힌트 보기’를 누르면 번호를 하나 늘립니다. 새 문제 단계가 열릴 때에는 0으로 돌아갑니다. 마지막 힌트에는 다음 힌트 버튼이 없습니다.

**읽어볼 것:** `currentHints()`는 별도의 힌트가 없는 실습에도 기존 실습 힌트와 단계 안내를 돌려줍니다. 모든 실습에 필요한 데이터를 어떻게 마련하는지 확인해보세요.

### 값을 읽어서 조작할 곳 강조하기

`updateCoach()`는 화면의 요소에 `coach-target`이라는 CSS 클래스를 붙입니다. 예를 들어 비밀번호 실습에서는 조건을 아직 채우지 않았다면 입력창을, 채웠다면 확인 버튼을 강조합니다.

이 함수가 정답을 승인하거나 점수를 주지는 않습니다. 화면에서 다음 행동을 안내하는 역할입니다. 실제 확인은 기존 `validateAnswer()`와 서버의 답변 처리기가 담당합니다.

**작은 연습:** `.coach-target`의 테두리를 바꿔보고 키보드 포커스 표시와 함께 읽히는지 확인하세요. 눈에 띄는 것뿐 아니라 작은 화면에서도 조작할 곳을 가리지 않는 것이 중요합니다.

### 변경 전후의 결과 설명하기

`comparisonMarkup(before, after, why)`는 세 가지 설명을 받아 비교 상자를 만듭니다.

| 입력 | 뜻 | 게임 규칙 실습의 예 |
| --- | --- | --- |
| `before` | 비교할 처음 상태 | 도토리 1점·방어 꺼짐 |
| `after` | 실험에서 확인한 상태 | 선택한 점수·방어 결과 |
| `why` | 차이가 생긴 이유 | 값과 조건이 게임 결과를 바꿈 |

`stepComparison()`은 실습에 맞는 내용을 준비하고, `learningRecapMarkup()`는 완료했을 때 원리를 정리합니다. 비밀번호는 입력한 원문을 복사하지 않고 길이와 조건만 설명합니다.

비교 화면의 예시가 실제 관찰인지 학습용 처음 상태인지 구별해서 적어야 합니다. 게임의 비교 기준은 초기 규칙이고, 확인 후 결과는 사용자가 테스트한 선택에서 만들어집니다.

### 다음 미완료 단계를 기억하기

`saveStudyCheckpoint(nextStep)`는 실습을 시작하거나 답을 맞힌 뒤 이어갈 단계를 기록합니다. 첫 단계를 맞혔다면 다음 단계인 1을 저장합니다.

혼자 연습일 때의 저장 형태를 보여주는 예제입니다. 아래 시드는 예시 값입니다.

```json
{
  "missionId": 0,
  "step": 1,
  "seed": 123
}
```

현재 입력값이나 비밀번호는 들어 있지 않습니다. 새로고침 뒤 입력과 게임은 현재 단계에서 다시 수행합니다. 화면에서만 저장한 단계는 공유 계정의 서버 판정에 사용하지 않습니다.

### 서버 진행으로 다른 기기에서도 이어가기

로그인한 사용자가 이어하기를 누르면 `resumeStudy()`가 `/api/attempts/current`를 다시 요청합니다. 서버는 세션에서 사용자를 찾고 그 계정의 가장 최근 혼자 실습을 조회합니다. 완료 여부와 유효 시간을 확인한 뒤 저장된 단계와 시드를 돌려줍니다.

```text
이어서 배우기 클릭
  → 서버에 최신 진행 요청
  → 실습 소유자·완료 상태·만료 확인
  → 해당 실습과 서버 단계 열기
  → 현재 단계의 입력·게임 다시 수행
  → 기존 답변 검증으로 다음 단계 진행
```

친구 방의 실습은 방 시작 시간과 결과 조건이 있으므로 이 혼자 실습 경로로 이어가지 않습니다. 방의 기존 화면을 사용합니다. 최신 실습이 끝났다면 그보다 오래된 실습을 갑자기 열지 않도록 서버 조회도 가장 최근 기록을 기준으로 합니다.

**직접 확인할 연습:** 비밀번호 실습의 첫 단계를 맞힌 뒤 창을 닫고 새로고침하세요. 메인의 ‘이어서 배우기’로 두 번째 단계가 열리는지 봅니다. 닉네임으로 참가한 경우에는 계정 복구로 다른 브라우저에서도 같은 단계를 확인할 수 있습니다.

### 내가 배운 내용을 메인에 모으기

`renderStudyDashboard()`는 완료 ID 목록을 설명 자료와 연결합니다. 완료한 실습에는 그 실습의 학습 목표를 보여주고, 진행 중인 실습이 있으면 이어하기를 표시합니다. 그렇지 않으면 다음 미완료 실습을 권합니다.

하나의 기능 안에도 역할이 나뉩니다. 저장 함수는 진행을 보관하고, 서버는 공유 기록을 검증하며, 화면 함수는 그 결과를 읽기 쉽게 보여줍니다. 각 함수의 입력과 결과를 연결해서 설명해보세요.
